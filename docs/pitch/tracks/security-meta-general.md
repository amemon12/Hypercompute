# Combined assessment of three lighter fits. Primary recommendation: Armadin Best Security Hack. Secondary: Cal Hacks Most Technically Complex. Meta and Best Hardware/Planet-First: weak, do not bolt on.

Fit 6/10, prize about $1556, effort about 7 h (estimate).

## Integration

Submission-count rule first: nothing at Cal Hacks 13.0 limits how many tracks one Devpost submission opts into. The organizer guide (the Google Doc) and hive.hackberkeley.org/prizes and devpost list dozens of tracks and only "highly encourage you to participate in at least one"; the only "selecting up to" text found is an unrelated 11.0 hot-sauce raffle. So one entry can opt into Armadin + Most Technically Complex + an overall prize at once. Caveat: Meta and some sponsors require separate opt-in/supplemental forms, and nothing was found stating a hard cap, so confirm at the Armadin/info desk.

(a) ARMADIN BEST SECURITY HACK, fit ~4/10 as-is, ~6.5/10 with one new guard. Armadin is Kevin Mandia's agentic offensive-security (AI red-team) company; its criteria still read "Coming soon!" (hive, updated Oct 24 6:13PM), so treat as general security judging. The encrypted Iroh tunnel, one-use HMAC-hashed invites (services/sessions.py redeem() consumes atomically), per-node credentials with hmac.compare_digest (services/nodes.py authenticate), binary allowlist (engine.py ALLOWED_BINARIES), consent caps (agent/managed.py ManagedConsent devices+max_disk), and FNV/SET_TENSOR_HASH seeding all protect the HOST from strangers. A security judge asks the reverse: what protects the FRIEND from the host? Peers run llama.cpp ggml-rpc-server, whose README says "Never run the RPC server on an open network or in a sensitive environment"; the repo carries critical CVE-2026-34159 (unauthenticated RCE via GRAPH_COMPUTE buffer=0, vulnerable <= b7991; pinned b11770 is past that by version order, inferred not tested) plus CVE-2024-42479/42478. join.py already tells the user "Only pair with a host you trust." That trust is the honest vulnerability to dramatize. Smallest integration that does real work: a peer-side RPC command firewall in the bridge the host already tunnels to (transport/client.py _serve_rpc -> bridge_tcp, which today is a blind byte pipe to 127.0.0.1:worker_port). Parse the llama.cpp RPC framing (already modeled in capacity/linkprobe.py: 1-byte cmd + uint64 len) and enforce on the peer side: reject GRAPH_COMPUTE tensors with buffer==0, bound SET_TENSOR offset+size to the allocated buffer, and surface a live "blocked N malicious frames" counter on the peer's local 127.0.0.1 status page (join.py line 686) and in /api/network. That turns an existing blind tunnel into an inspected one, defends against the exact CVE class in a dependency the project ships, and is demoable by firing a crafted buffer=0 frame and watching the peer refuse it. This is a code DESIGN only; repo is READ-ONLY this session, user implements during the event for the prior-work rule. Lives in a new module beside transport/client.py plus a small struct parser reusing linkprobe.py.

(b) META BRINGING PEOPLE CLOSER TOGETHER WITH AI, fit ~3/10. Judged on strengthening human CONNECTION, essential+well-integrated AI, originality, working demo; prize is a Round 2 invite at Menlo Park (no cash). "Multiplayer computing / your friends' laptops join one pool" is a genuine social hook and the join-code flow is live-demoable, but the connection here is machines pooling compute, not people connecting with each other, and the AI (the LLM being served) is the payload, not the thing strengthening connection. Fitting it means bolting a social app onto an infra project, which the sponsor-penalty note warns against. Skip unless a real shared-session product is built on top; do not reframe infra as social.

(c) CAL HACKS GENERAL. Most Technically Complex, fit ~8/10: three OSes on stock llama.cpp, MoE-aware exact planner agreeing with a brute-force oracle, ~2000 tests, real 671B/1T runs across a GB10 + RTX laptop + M4 Airs over Iroh QUIC. This is the natural home; the security guard above adds protocol-level depth that reinforces it. First Overall, ~4/10 stretch (needs a one-sentence human story, infra rarely wins 1st). Best Hardware Hack, ~2/10: it is software across commodity machines, no built hardware, do not chase. Best Planet-First, ~3/10 and this is the candid part: measuring energy-per-token on reused laptops vs a datacenter GPU is technically feasible tonight but the result likely argues AGAINST pooling. On the GB10 host, nvidia-smi reports power.limit as [N/A] (confirmed here on the RTX 5070 Ti: 21.32W draw, limit N/A; same N/A pattern documented for GB10/DGX Spark), and nvidia-smi wattage is GPU-only (box is ~240W peak). Macs need macmon (MIT, sudoless, cpu/gpu/ane/sys_power) since powermetrics needs sudo and the rental password is never entered; macOS 26 on the Airs may have broken the sudoless power channel (macmon notes macOS 27 did). Even with clean numbers, pooling costs decode (0.83x on 671B) and adds 3-4 laptops drawing power, so joules/token pooled is probably WORSE than the GX10 alone; the honest Planet-First angle is "reuse existing idle laptops instead of buying a datacenter GPU" (embodied carbon, not operating energy), which is a narrative, not a measured win. Recommend not opting into Planet-First.

## Demo moment

Fire a crafted llama.cpp RPC GRAPH_COMPUTE frame with buffer==0 (the CVE-2026-34159 shape) at a joined friend's peer. Today the host-to-peer tunnel is a blind byte pipe, so it would reach ggml-rpc-server. With the new peer-side RPC firewall, the peer's local 127.0.0.1 status page flips a "blocked 1 malicious frame" counter and the stream stays clean, on screen, live. Pairs with the existing join-code handshake and per-peer layer lines for the Most Technically Complex pitch.

## Risks

Prior-work disqualification is the dominant risk: the repo was built Oct 20-24 before the event and the Hive FAQ/Devpost/MLH ban reusing it; any Cal Hacks entry must be rebuilt live or cleared with organizers (see docs/pitch/CALHACKS-13-ULTRAPLAN.md P1/P2/P3). Armadin criteria are still "Coming soon!" so the exact rubric is unknown; the guard assumes general security judging. The CVE-2026-34159 claim that b11770 is patched is inferred from version ordering, not tested, so demo the guard blocking the frame rather than claiming the upstream fix. The RPC firewall must parse framing without breaking the hot path (reuse linkprobe.py structs; GRAPH_COMPUTE tensor arrays are nontrivial to parse under time pressure). Planet-First measurement is feasible but likely shows pooling as net-worse on operating energy, and GB10/Mac power sensors are partly N/A or sudo-gated; do not opt in expecting a win. Confirm no hidden per-submission track cap and that Meta/others' separate opt-in forms are filed. Repo is private with no license; give judges collaborator access rather than publishing untriaged.
